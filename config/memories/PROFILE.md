# PROFILE

## User Role
- Uses Codex as a long-term technical collaboration assistant.

## Technical Level
- Gives precise output and formatting constraints.

## Communication Preferences
- 默认使用中文。
- 需要长期遵守已确认的回复格式约束。

## Working Preferences
- 需求沟通偏好 = 先从上下文和可读取证据消除歧义；仅当缺失信息会实质改变目标、范围、验收标准或风险且无法合理推断时提问。用户表述不专业、模糊或带情绪时，先还原真实诉求、场景、边界和验收标准，再进入技术方案。
- 偏好结论优先、低冗余、可跨会话继承的协作方式。
- 命令执行偏好 = 优先使用 PowerShell 7；若环境缺少 `pwsh.exe`，需先说明后再决定是否回退。
- 文件创建偏好 = 新建文件默认使用 UTF-8。
- 文件归档偏好 = 文件按用途归档，而不是按文件数量决定；介绍、说明、README 等文档默认放入 Docs 文件夹，代码、数据、图片、视频等按对应用途放入子文件夹，根目录只保留必要的入口文件。
- 写作大纲偏好 = 需要列大纲时采用原子化、事无巨细的方式拆分内容，面向完全小白读者显式列出前置知识、术语、步骤、过渡、示例、疑问和验证点；用户授权直接成文或要求跳过阶段时，不额外等待确认。
- 源码换行偏好 = 修改现有源码时保留原文件编码及 CRLF/LF 换行风格；不要因编辑工具自动转换换行符而制造整文件 Git 差异，若发生 CRLF→LF 转换应先恢复后再提交。
- 代码修改偏好 = 使用 `gyc-code-comments` Skill 添加清晰中文注释；有意义的新增、修复、修改分别使用 `added/fixed/modified by gyc YYYY-MM-DD` 标记，格式为“标记在前、全角冒号后写说明”：单行 `added/fixed/modified by gyc YYYY-MM-DD：说明`，多行起始行 `added/fixed/modified by gyc YYYY-MM-DD start：说明`，结束行保持简短；函数文档说明职责、参数、返回值和必要单位；复杂公式、数值方法、坐标变换和并发逻辑按步骤注释；新增运行日志和错误打印使用中文；较长源码按职责使用中文横幅注释分区。
- 代码变更流程 = 先完成只读调查，再说明具体修改方案、拟改代码和验证范围；得到用户明确确认后修改文件。确认对已说明的变更范围持续有效，无需按文件或工具调用重复确认；超出范围时重新提出。等待确认期间继续不依赖该确认的只读工作。
- 代码简化偏好 = 涉及新增、修改、重构或修复代码时先调用 `ponytail` Skill，按最小可行实现、复用现有能力、标准库/原生优先和避免无请求抽象的原则审视方案；纯阅读、诊断、解释、文档和文件整理不强制调用。
